## 一、修复范围

本轮只处理两个问题：

1. 刷新地址后 Edge 收藏夹出现大量成对重复；
2. 直登账号管理首次导入或删除后重新导入账号时，账号变成“未参与”，且当前只能逐个加入上号列表。

以下内容不纳入本轮：

- 不切换 64 位主程序架构；
- 不删除大漠兼容代码；
- 不修改 9 窗、31 窗准备、排列、登录主流程；
- 不修改 HWND/PID/X5Game/CDP 归属验证；
- 不修改加速器核心倍率脚本；
- 不自动删除用户当前已经重复的收藏夹。

## 二、实机问题一：收藏夹成对重复

### 2.1 实机现象

本次实机测试经历了两次刷新：

1. 32 位源码环境缺少 `requests`，HTTP 路径失败后程序自动回退 Playwright；用户中途停止，但停止前已有前若干账号完成刷新和收藏夹写回；
2. 随后使用 64 位 Python 执行“刷新全部”，纯 HTTP 路径成功。

第二次日志中，每个账号只出现一次刷新和一次 `bookmark_success`，没有同一账号被刷新两遍的证据。但刷新完成后，Edge 收藏夹出现大量成对重复，包括：

- 本轮刷新产生的命名账号；
- 本轮未处理的旧数字收藏项，例如 `1、2、3……`。

用户确认：以前版本执行过同类刷新，没有出现这种整套重复。因此本问题应优先按“近期收藏夹写回回归”调查，不能简单归因于 Edge 一直存在的同步问题。

### 2.2 当前高风险行为

当前实现存在以下组合风险：

1. `BookmarkUrlUpdater.update()` 每成功一个账号，就重新读取并完整替换一次 Edge `Bookmarks`；
2. 当前版本新增了“路径不存在时自动创建中间目录和最终收藏项”；
3. 收藏夹根目录身份主要依赖类似 `roots/bookmark_bar/children/N` 的结构下标；
4. 当前自动化只验证临时 JSON、校验和和原子替换，没有覆盖 Edge 重启、同步、`Bookmarks.bak` 恢复或云端合并后的真实结果；
5. 缺少 `requests` 被当成 HTTP 登录失败，触发了静默 Playwright 回退和浏览器弹出。

可能的回归链：

```text
路径匹配未命中
→ 当前版本自动新增节点
→ 多账号逐条完整重写 Bookmarks
→ Edge 同步、恢复或结构路径漂移进一步放大
→ 出现整套成对重复
```

上述回归链仍需通过当前 `Bookmarks`、`Bookmarks.bak`、父目录、GUID 和同步状态继续验证，不能在实现前写成最终确定根因。

## 三、收藏夹最终业务规则

### 3.1 收藏夹导入能力必须保留

用户明确需要把刷新后的账号导入浏览器收藏夹，因此不能用“以后永远只保存上号器本地链接库”来规避重复。

刷新地址弹窗应提供并记忆一个明确选项：

```text
☑ 刷新成功后同步/导入收藏夹
```

- 勾选：本批刷新完成后，执行一次整批收藏夹更新和缺失项导入；
- 未勾选：只更新上号器本地直登链接库，不改浏览器收藏夹。

### 3.2 首次导入时最后一次性写入

首次导入 49 个账号时，不能每刷新一个账号就写一次收藏夹。

正确流程：

```text
刷新全部账号
→ 在内存中收集本批成功直登 URL
→ 生成整批收藏夹计划
   更新已有 N
   新增缺失 M
   冲突 K
   跳过 S
→ 全部校验通过
→ 备份一次 Bookmarks
→ 写临时文件一次
→ 原子替换 Bookmarks 一次
→ 重新读取并验证一次
```

因此，即使本批同时存在“已有收藏项”和“需要新增收藏项”，也应正常写入：

```text
已有 40 个 → 原位更新 URL
缺失 9 个 → 安全新增
冲突 0 个 → 整批写入一次
```

### 3.3 已有收藏项的处理

完整路径唯一命中的收藏项：

- 只更新 URL；
- 保留原 GUID；
- 保留原 ID；
- 保留原位置和其它未知字段；
- 不创建第二份。

### 3.4 缺失收藏项的处理

完整路径不存在时，可以按照账号配置里的明确 `bookmark_path` 安全导入：

- 必要时创建缺失分组目录；
- 必须限制在已验证的账号根目录内；
- 父路径逐级必须唯一；
- 同一路径不能存在多个同名同类型节点；
- 不能为了完成导入，在同一完整路径下追加第二份。

### 3.5 同名账号的合法规则

唯一性以“规范化完整路径”为准，不能以最后一个名称全局判断。

以下路径全部合法：

```text
账号/第一层/1
账号/第二层/1
账号/第三层/1
账号/第四层/1
```

规则：

```text
不同分组下同名：允许
同一完整路径重复：冲突
同一父目录同名同类型：冲突
```

### 3.6 稳定身份映射

上号器对已经确认或创建的收藏项，应保存稳定映射：

```text
account_key
→ bookmark GUID
→ 规范化完整路径
```

后续再次刷新时：

1. 优先按稳定 `account_key` 找到历史映射；
2. 联合校验 GUID、完整路径和名称；
3. 命中原节点后只更新 URL；
4. 历史映射存在但 GUID 找不到时，不允许自动再创建一份，必须标记冲突。

### 3.7 根目录身份保护

账号根目录不能只依赖可漂移的 `children/N` 下标，应同时保存并校验：

- 根目录 GUID；
- 根目录名称；
- 结构路径。

三者任意不一致时，停止本批收藏夹写入。

### 3.8 并发修改保护

整批开始时记录原 `Bookmarks` 文件哈希；最终替换前再次计算。

```text
哈希未变化 → 允许原子替换
哈希已变化 → Edge 或其它程序修改过文件，放弃写入
```

浏览器正在运行时禁止写回。收藏夹同步状态无法安全确认时，只保存上号器本地链接，并明确显示“收藏夹未写回”。

### 3.9 冲突处理

以下情况属于真正冲突：

- 同一完整路径出现多个节点；
- 同一父目录下存在多个同名同类型节点；
- 同一层级同名文件夹和 URL 类型冲突；
- 历史 GUID 指向另一条完整路径；
- 根目录 GUID、名称和结构路径不一致；
- 整批处理期间 `Bookmarks` 文件被外部修改。

有冲突时：

- 本批刷新成功的直登 URL仍保存到上号器本地链接库；
- 收藏夹整批不写；
- 显示具体冲突路径和数量；
- 不能写一半，也不能悄悄新增第二份。

## 四、当前重复收藏夹的恢复方案

不得直接按名称删除一半。需要提供独立的“收藏夹检查/恢复”工具。

默认行为必须是只读预览：

1. 读取当前 `Bookmarks`；
2. 读取 `Bookmarks.bak`；
3. 读取用户选择的历史自动备份；
4. 输出重复节点的：
   - 完整父路径；
   - 名称；
   - GUID；
   - ID；
   - URL；
   - 来源字段；
   - 建议保留项；
5. 生成恢复或去重计划；
6. 用户明确确认后才执行；
7. 执行前再次备份当前收藏夹。

必须保护以下两份实机备份：

```text
上号器数据/backups/Bookmarks_Edge_Default_20260712_171250_423586.json
上号器数据/backups/Bookmarks_Edge_Default_20260712_172302_602736.json
```

## 五、HTTP 依赖和 Playwright 回退规则

### 5.1 缺少依赖不是登录失败

缺少 `requests` 属于运行环境预检错误，必须在第一条账号开始前检查。

正确行为：

```text
缺少 requests
→ 弹出明确提示
→ 停止本批刷新
→ 不打开 Playwright 浏览器
```

### 5.2 真实 HTTP 登录失败

只有依赖完整且真实 HTTP 登录失败时，才允许提供 Playwright 回退。

回退必须由用户明确确认，不能在“刷新全部”过程中静默弹浏览器。

## 六、实机问题二：直登账号默认未参与

### 6.1 已确认根因

`LoginAccountRosterStore.reconcile()` 当前逻辑：

- 当前账号库中不存在的账号状态会从 `_states` 删除；
- `_seen` 却永久保留历史 key；
- 同一账号删除后重新导入时，状态已经丢失，但 key 仍在 `_seen`；
- 新状态使用 `included = key not in _seen`；
- 因此账号被错误设置为 `未参与`。

GUI 当前还使用：

```python
Treeview(selectmode="browse")
```

只能单选，加入/移除也只处理一条，所以大量账号只能逐个点击。

## 七、直登账号管理最终规则

### 7.1 默认参与

- 真正首次导入的新账号：默认 `已参与`；
- 首次导入 49 个账号后：默认全部进入上号列表；
- 用户仍可批量移除不需要参与的账号。

### 7.2 重新导入恢复历史状态

- 账号暂时从刷新地址账号库消失时，不立即删除其参与状态；
- 同一稳定 `account_key` 重新导入时，恢复最近一次用户明确设置的参与状态；
- 没有明确历史状态时，默认参与；
- 旧 `seen_keys` 只兼容读取，不再决定 `included=False`。

### 7.3 多选与批量操作

表格改为：

```python
Treeview(selectmode="extended")
```

增加操作：

- 选中账号加入上号列表；
- 选中账号移出上号列表；
- 当前筛选全部加入；
- 当前筛选全部移出。

“当前筛选全部”应同时遵守状态筛选和分组筛选。例如：

```text
分组筛选=第一层
状态筛选=未参与
→ 当前筛选全部加入
→ 只处理当前可见的第一层未参与账号
```

批量操作应：

- 一次更新内存；
- 一次原子保存；
- 一次刷新表格；
- 显示影响数量；
- 不逐条重复写文件。

参与状态变更不能删除刷新账号、不能删除直登链接，也不能破坏登录顺序。
